# PDF 补图模式设置（未发布开发改动）

## 设置与行为

设置入口位于「沉浸式双语」面板内，「主力翻译模型与行为」之后、
「排版美化：字体与视觉框架」之前，独立小组为「PDF 图形补充」。
下拉框名为「缺图补充」，选项为关闭、点击补图（默认）、自动补图。
该功能在本地处理，独立于自动翻译和「翻译表格与图块」。

偏好键：`extensions.zotero.reading-bilingual.figureMode`，值为
`off` / `manual` / `auto`。未设置或无效值回到 `manual`。

- 关闭：不扫描或复制 SDT，不创建占位；立即移除已有补图，断开监听并清理状态。
- 点击补图：只创建按钮，用户点击才排队渲染。
- 自动补图：图形接近视口 400 像素时加载；每个视图内串行处理。
- 手动与自动切换保留已有图片。切回手动后，尚未开始的自动任务跳过；
  已经进入原生渲染器的任务可以完成。关闭后忽略迟到结果。
- 自动失败仅显示错误和重试按钮，不会在每次滚动或定期检查中重复尝试。

用户截图证明桌面上仍有按钮等待点击，不能仅凭旧代码存在观察器就断言
实际自动补图成功。本次用稳定字符串标识匹配观察器目标，避免依赖 Gecko
对象包装的身份一致性；同时增加可见区域检查，作为观察器未回调的后备。
未将截图直接作为该对象身份问题的根因证明。

## 验证

- 单元测试 38 项：默认与无效偏好、关闭无扫描、立即切换、自动触发、
  不同目标包装、失败不自动重试、已载入图片保留、取消待执行自动任务等。
- Firefox 浏览器测试 6 项：原有 5 项以及实际设置脚本的模式保存、重新读取、
  键盘操作、已打开阅读视图的即时变化。
- Gecko 权限回归 2 项：此前的精确权限错误回归，以及系统权限插件从手动
  切到自动后调用内容环境渲染、裁剪、解码。窗口外测试使用内容环境提供的
  可见矩形，以覆盖无观察器回调的后备路径；不是桌面视口实测。
- 实际 PDF 常规集成 1 项：自动模式下，两篇问题 PDF 共 24 个补图载入。
- 实际 PDF 权限集成 1 项：手动模式下，以系统权限插件和内容权限原生渲染器
  加载两篇 PDF 的 24 个图形。原 PDF、SDT、译文缓存哈希不变。

证据存放于工作区 `.diagnostics/zotero-pdf-figures/figure-modes/`。
`figure-settings.png` 是真实设置内容经过 XUL 容器布局适配后的 Firefox 预览，
用于核对控件和文案，不是 Zotero 桌面截图。

## 打包与版本

保持 manifest 为 1.6.13，不创建新提交、不推送远端。
测试包为 `zotero-reading-bilingual-1.6.13-figure-modes-test.xpi`，
放入用户指定的 `F:\111office\zotero\plugins`。
保留此前安装包。最终包文件比对与哈希记录在 `build-result.json`。

未在用户的 Windows Zotero 中安装并操作此版设置，桌面效果仍需复核。
此前边界推断、内存容量上限和依赖 Reader 内部接口的限制仍然存在。
