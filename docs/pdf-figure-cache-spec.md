# 补图资源与本地缓存规范

本轮沿用已授权的单图补充与三档模式，保留当前工作树和版本 1.6.13；
不提交、推送或修改用户日常 Zotero 配置。先前候选包在源码变化后视为过期。

## 行为与边界

1. 关闭不触发图形读取；点击模式首次等待点击；自动模式近视口才读取。
   已经读过的图离屏卸载后，返回时自动恢复，保留其布局尺寸。
2. 读取路径：有限内存缓存 → 本地 PNG → 原生区域渲染。
   同一键的并发请求合并；失败可重试，不存失败结果。
3. 仅保存成功解码的 PNG、尺寸和裁剪信息。缓存键包含 PDF 内容指纹、
   SDT/补图算法版本、候选范围、旋转与渲染参数；插件版本独立处理。
4. PNG 和小型元数据存于 Zotero cache 下的插件独立目录。
   写入原子化；损坏、孤立或中断文件视为未命中；磁盘错误不阻止当前阅读。
5. 内存按图片像素与编码数据估算设预算，优先清理离屏内容；远离视口立即卸载。
   正在显示的图片可以暂时超过预算，不能用该估算声称应用 RSS 的硬上限。
   磁盘设字节与条目上限，按最近使用淘汰；初始参数依据基线与压力测试调整。
6. 缓存服从三档模式。关闭功能清理内存和显示但保留磁盘；清理缓存不会删
   原 PDF、SDT、译文或其他插件缓存。清理时既有异步任务不能写回过期结果。
7. 设置组增加缓存开关、实际磁盘用量和清理反馈；无需显示技术参数。
8. 文件变化、关闭/禁用、迟到任务、磁盘失败和缓存失效必须有验证。

## 实现顺序与测试边界

- 缓存模块的公开读写、复用、限额、清理接口：Node 临时目录验证真实文件。
- 补图入口的按钮、显示、卸载、恢复、模式切换：单元、Firefox 真实输入。
- 系统权限/内容权限与实际 IOUtils：Gecko 权限测试。
- 两篇问题 PDF 冷/热读取：匹配安装版 Reader/PDF.js，核对图像与源文件哈希。
- 原生桌面：尝试隔离配置中实际安装、打开原问题 PDF 和阅读模式；
  无法完成的桌面操作继续明确标记待复核，不用替代测试宣称完成。

## 文件与检查命令

新增 `content/scripts/figure-cache.js`；原补图脚本只负责阅读视图与裁剪。
设置沿用 preferences.xhtml/preferences.js，测试在 tests/，报告在 docs/。
JavaScript 沿用现有对象接口、异步函数与无新增运行依赖的风格。

```
npm test
npm run test:browser
node --test tests/gecko/figure-permissions.test.cjs
# 使用本机 ZRB_PDF_CASES 后运行：
npm run test:pdf
npm run test:gecko
python tools/check-delivery.py --xpi <测试包> --copy <交付副本>
```

测试配置、论文、临时浏览器/桌面文献库和诊断产物只保存在工作区诊断目录。
只对插件独立缓存目录中经过校验的文件执行清理，不递归删除目录。

## 验收

所有新增行为测试通过；实际图形正确；热读取减少原生渲染调用；长文和多标签
下保留量受控；离屏卸载不改变布局；原始文件不变；交付包与当前源码一致。
代码实现、自动测试、隔离桌面、用户日常配置复核和发布各自单独记录。
